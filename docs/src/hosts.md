# Hosts

|host|arch|role|
|---|---|---|
|`voyager`|x86_64|Framework Laptop 12, niri + noctalia (Umbriel as a second greeter session), remote-builds on endeavour|
|`endeavour`|x86_64|the workhorse. jellyfin, immich, kanidm, traccar, opencloud/collabora, suwayomi + flaresolverr, ollama + librechat (chat.lvdar.nl, local models + OpenRouter) on a Tesla P100, tangled (knot + spindle), a PDS, minecraft (packwiz packs from the `modpacks` input, also served to players at packs.lvdar.nl), attic, `services.site` (lvdar.nl), DOMjudge (judge.lvdar.nl: podman containers with CHipCie practice contests; extra judge languages live in `services/domjudge/languages.nix`), the VPN-confined `*arr` stack, the prometheus/grafana/loki/alloy monitoring, and the unprivileged `agent` user for coding agents (`services.coding-agents`, see [Networking & SSH](networking.md#coding-agents-on-endeavour)). ZFS `tank` with sanoid/zed; restic offsite|
|`gaia`|x86_64|public VPS and the fleet's only ingress. Runs the self-hosted **NetBird control plane**, and `netbird-proxy` terminates TLS and forwards to endeavour over the mesh. Also crowdsec, ntfy, stalwart (mail.lvdar.nl, also the vandar.tel domain) with Bulwark webmail (webmail.lvdar.nl) and the holiday and birthday calendars, unbound, the gatus status page, and the vhosts its own nginx serves directly (`localVhosts`). Pangolin used to be the ingress and is **decommissioned** — do not reintroduce it|
|`pioneer`|aarch64|Raspberry Pi 3; built on endeavour (binfmt) via voyager's remote builder, never on the Pi. Publishes endeavour's **iDRAC** (`services.idrac`) to the mesh — it shares nothing with endeavour but a switch, which is the whole point: out-of-band management proxied by the machine it exists to recover is not out-of-band|

Hardware comes from committed **nixos-facter** reports (`hosts/_facter/<host>.facter.json`) plus **disko** layouts in `hosts/_hw/<host>/`. voyager, endeavour and gaia use impermanence (pioneer does not).

## Host facts

Each host registers `den.hosts.<arch>.<host> = { users.<user> = {}; meshAddress; server; deployAddress; deployByDefault; sshHostKey; }` in `modules/den/hosts/<host>.nix`; the facts are declared in `modules/den/schema.nix` and are plain data any module can read without evaluating that host.

|fact|meaning|
|---|---|
|`meshAddress`|NetBird mesh IPv4, assigned at enrolment; re-check after re-enrolling a peer|
|`server`|headless server: gets `roles.server`|
|`deployAddress`|what deploy-rs connects to (default `<host>.nb.lvdar.nl`; gaia uses `lvdar.nl`)|
|`deployByDefault`|servers only: whether a bare `deploy` includes it and `DeployBehind` watches it (default true; false on pioneer)|
|`sshHostKey`|the host's ed25519 SSH host public key (`ssh-ed25519 AAAA…`, no comment). Pinned in every host's `known_hosts` (core.ssh) and used by endeavour to authorize remote-build clients. Read it with `cut -d' ' -f1,2 /persist/etc/ssh/ssh_host_ed25519_key.pub` on the host (`/etc/ssh` on pioneer), or `ssh-keyscan -t ed25519 -p 2222 <host>.nb.lvdar.nl`. A reinstall with a fresh key updates this fact and `.sops.yaml` together|

## voyager

The laptop and the only workstation; switches locally with `nh os switch`. Builds offload to endeavour ([Remote builds](deployment.md#remote-builds)), and its sshd is reachable over the mesh only.

### Hardware

Framework Laptop 12 — Intel Core 3 304 (Wildcat Lake) with the Xe3 iGPU on `xe`, Intel BE213 Wi-Fi 7, 16 GB DDR5 in one slot (single channel), 256 GB 2230 NVMe, 1920×1200 touchscreen on a 360° hinge, Framework stylus (MPP 2.0; the firmware's stylus protocol is set to MPP, since USI mode has reports of a stuck eraser on Linux), backlit keyboard, no fingerprint reader, Ethernet expansion card. Hardware specifics live in `hosts/_hw/voyager/framework-12.nix`; facter (`_facter/voyager.facter.json`) and disko (`_hw/voyager/disko.nix` on `/dev/nvme0n1`, LUKS + btrfs, 16 GiB swapfile) cover the rest.

The hardware module pins `linuxPackages_latest` (Wildcat Lake needs ≥ 7.1) and loads `pinctrl_intel_platform` before `soc_button_array` for the tablet-mode switch, both behind `lib.warnIf` guards, and adds `intel-media-driver` for VA-API (H.264/HEVC/AV1 decode on the Xe3; Mesa has no Intel video driver). BIOS updates come through fwupd, announced on ntfy by `core.firmware-updates` ([Firmware updates](install.md#firmware-updates)). `eDP-1` runs at scale 1 under both compositors (niri would pick 1.5): the Cozette pixel font is only crisp at whole multiples of its 13 px grid, and fontconfig snaps it down, so at 1.5 text shrinks against everything else. The same holds below 1: the desk monitor (a Samsung S24F350, matched by make/model/serial so any port works) mangles text at 0.8, so it also runs at 1, left of the panel with bottoms aligned, set identically in both compositors' output sections. Try other layouts live with `wlr-randr` before changing them.

**Hibernation** resumes through systemd's `HibernateLocation` EFI variable; nothing hard-codes `resume=`/`resume_offset=` (see [Hibernation](install.md#hibernation) for the fallback).

**The touchpad** (PixArt `PIXA3854`) fails two ways, each leaving no cursor while the touchscreen still works. After hibernation it can come back silent, with no interrupts: the hardware module's `touchpad-resume-rebind` unit re-probes it through `i2c_hid_acpi` after every resume from hibernation. On some cold boots and resumes it also never enters precision-touchpad mode and reports through its legacy Mouse collection instead. That collection's unsigned relative motion only runs down and right, so the first touch throws the cursor off-screen. The `touchpad-mode-watch` unit watches that Mouse node, which sends nothing in touchpad mode, and re-probes the touchpad on its first motion. By hand: `sudo sh -c 'd=/sys/bus/i2c/drivers/i2c_hid_acpi; echo i2c-PIXA3854:00 >$d/unbind; echo i2c-PIXA3854:00 >$d/bind'`.

**Secure Boot** is on: `cosmos.system.boot.secureBoot` swaps GRUB for lanzaboote with the host's own keys, and the hardware module also enrolls Framework's firmware keys. Turning it on, and reinstalling with it on: [Secure Boot](install.md#secure-boot).

### Desktop

- **niri + noctalia** is the base desktop, behind the noctalia greeter. The greeter's session picker also offers **Umbriel**, the Umbriel compositor with the same shell for experimenting (`desktop.umbriel` and `home.umbriel`, bodies in `desktop/_umbriel/system.nix` and `home/desktop/_umbriel/home.nix`); log out to switch. The greeter preselects the last session picked (its `sync.toml`, persisted), since `defaultSession` is unset. Umbriel's units are bound to `umbriel-session.target` and niri's to `niri.service`, so each session runs only its own. Umbriel's keybinds copy niri's by hand; validate edits with `umbriel config validate`.
- **Theme**: Everforest, dark by default; `theme light|dark|toggle` or noctalia's light/dark toggle switch the whole session live under either compositor ([Theming](theming.md)).
- **Workspaces and monitors**, the same under both compositors: each monitor numbers its own workspaces, and `Mod+1..9` / `Mod+Shift+1..9` act on the focused one. These are the physical digit-row keys whatever the layout: neither compositor binds keycodes, so keyd (`desktop.keyd`) sends Mod + each digit key as a key no keyboard here has (`XF86LaunchA`, `XF86LaunchB`, `XF86DOS`, `XF86Finance`, `XF86Launch5`–`9`; the table is `workspaceKeys` in `keyd.nix`), and both bind those. Binding the printed symbols broke across layouts, since us(dvp)'s Shift turns `[` into `7`. Under niri they are dynamic, so a number past the last workspace lands on the empty one at the end; Umbriel keeps a persistent 1–9 per monitor. `Mod+Alt+H/J/K/L` focuses the monitor in that direction, `Mod+Alt+Shift+H/J/K/L` moves the column there. Unplugging a monitor moves its workspaces to the remaining one, and they return when it is reconnected.
- **Tablet mode** (`desktop.tablet`): folding the hinge makes the firmware disable keyboard and touchpad, and the tablet-mode switch shows the on-screen keyboard (wvkbd, kept running hidden) and the noctalia dock (launcher button, pinned and running apps). niri's `switch-events` do both. Umbriel has no switch events: a root `tablet-mode-switch` unit watching libinput records the state in `/run/tablet-mode`, and the session's `tablet-mode.path` applies it (also at login, for a session started folded). wvkbd 0.20 is patched to bind `wl_compositor` at most at the advertised version; unpatched it dies under Umbriel. A second patch (`desktop/_wvkbd-dvorak-hide.patch`) lays the letters out as Dvorak and adds a ▾ key that hides the keyboard; a two-finger swipe up from the bottom edge brings it back. It takes about a quarter of the screen (`-L`/`-H`). iio-niri rotates the screen from the accelerometer (under Umbriel: `umbriel-autorotate`). Touch and stylus are mapped to `eDP-1` and follow rotation. All of it is inert on hardware without the sensor or switch.
- **Touch gestures** (neither compositor has touchscreen gestures; niri's upstream PR [#3771](https://github.com/niri-wm/niri/pull/3771) is a draft): lisgd reads `/dev/input/touchscreen` (a udev symlink, `uaccess` for the seat user) and runs compositor actions. One-finger swipes count only from a screen edge: up from the bottom toggles the overview (under Umbriel it only opens it, since touching the overview already closes it), in from the left/right edge focuses the column on that side, down from the top opens the control center. Two fingers up from the bottom toggles the keyboard. Three and four fingers copy niri's touchpad gestures, the content following the fingers: three vertical switch workspaces, three horizontal switch columns, four up/down open/close the overview. Three fingers down from the top edge close the window. Unlike on the touchpad these fire once when the fingers lift (one workspace or column per swipe, within 0.8 s), and the window under the fingers sees the touches too. lisgd reads the orientation only at startup, so a wrapper restarts it when the screen turns: `lisgd-niri` (desktop/tablet.nix) polls niri after accelerometer changes, `lisgd-umbriel` (home/desktop/_umbriel/home.nix, same gestures with Umbriel's actions) follows `umbriel subscribe outputs`.
- **Without a keyboard**: unlock LUKS with a YubiKey touch (FIDO2, enrolled without a PIN) and log in at the greeter with a YubiKey (u2f, empty password). Pulling the YubiKey locks the session, unless a YubiKey is back within 3 s: swapping a Framework expansion card drops it for about a second. Reinserting a YubiKey and touching it unlocks the session again with no Enter (`yubikey-unlock`, a user unit started by udev, checks the touch with pam_u2f against the same `/etc/u2f_mappings` as login). Inside the session, yubikey-touch-detector shows a notification while any FIDO request waits for a touch.
- **Apps** for the stylus and media: Xournal++ (notes, PDF annotation), Rnote, Krita, and mpv with the touch-friendly uosc UI.
- **Games**: Steam with Proton-GE (`roles.gaming`), PrismLauncher with the MCSR toolchain (`home.minecraft`), and GeForce NOW (`home.geforce-now`), the web client in a Chromium app window with its own persisted profile. It is the way to play anti-cheat titles such as Fortnite, which refuse Proton.
- **genix** (`services.genix-boot`): the GEHACK contest workstation as a second boot entry (under Secure Boot a signed UKI), booted once by the `genix` command. A live system on the host's kernel, LUKS, keyboard layout (from the passphrase prompt on) and read-only `/nix`; `~/shared` in genix is `~/genix` on the host (the `/persist/genix` subvolume). It refuses to boot while voyager is hibernated.

## endeavour

The workhorse and the fleet's build machine: voyager's remote builder including aarch64 emulation ([Remote builds](deployment.md#remote-builds)), the knot, and prometheus, whose `DeployBehind` alert compares every server with the knot's `main` ([Deployment](deployment.md)).

CPUs 0-3 belong to DOMjudge's four judgehosts: `system`, `user` and `machine.slice` run on the other CPUs, the judge cores' hyperthread siblings (36-39) are offline, and the judge cores are held at the 2.1 GHz base clock (`domjudge-judge-cores`; stopping it undoes both). Judging times then stay within ±1.5% whatever else the host does; a busy sibling slowed runs 2.2× and turbo moved them ±8%.

## gaia

The edge: NetBird control plane, `netbird-proxy`, `localVhosts`, oidc.idp.

**Stalwart 1.x** keeps every setting in its database. `services.stalwart.provision` replays the declared ones over the loopback management API (`127.0.0.1:8088`) after each start, using the module from nixpkgs PR #552103, vendored in `services/_stalwart` until it lands. Listener and role changes take effect only on the next `stalwart` restart. Anything not declared there is database state. That includes blocked catch-all addresses: create them as `MemoryLookupKey` in namespace `blocked` with `stalwart-cli` as the recovery admin (`STALWART_URL=http://127.0.0.1:8088 STALWART_USER=admin`, password `keys/stalwart/admin`), and they take effect after `stalwart-cli create Action --json '{"@type":"ReloadLookupStores"}'`. It also includes app passwords, which the admin cannot set: the account creates them itself in Bulwark's settings. Bulwark signs in with kanidm's `stalwart` client and calls JMAP on mail.lvdar.nl directly from the browser (CORS).

**vandar.tel** (`extraDomains`) is a second mail domain whose catch-all also lands in `lars@lvdar.nl`. Its DNS lives in Cloudflare by hand, like lvdar.nl's: MX `mail.lvdar.nl`, SPF `include:spf.jetsmtp.net`, DMARC `p=quarantine`, and `jetemail._domainkey` CNAME `dkim.jetsmtp.net`. gaia's `keys/cloudflare/dns` token can edit the zone, but only from gaia's address. Family members get `<user>@vandar.tel` as an alias on their `<user>@lvdar.nl` account, which kanidm logins create. Both are database state, because Stalwart's OIDC directory never imports aliases. To add one, add the person to kanidm `mail-users`, then pre-create the account with its alias so mail is delivered before the first login, using `stalwart-cli apply --stdin` as the recovery admin:

```json
{"@type":"upsert","object":"Domain","matchOn":["name"],"value":{"lvdar":{"name":"lvdar.nl"},"vandar":{"name":"vandar.tel"}}}
{"@type":"upsert","object":"Account","matchOn":["name","domainId"],"value":{"<user>":{"@type":"User","name":"<user>","domainId":"#lvdar","aliases":{"0":{"name":"<user>","domainId":"#vandar"}}}}}
```

`services.holiday-calendar` mirrors Dutch public holidays and observances (Google's `nl.dutch#holiday` feed) and the school holidays of all three regions (agenda-abonnement.nl; a holiday with the same dates in several regions is one event, titled with those regions, or none when all three share it), plus computed carnaval (Sunday to Tuesday before Ash Wednesday) and, in years where zuid's advised spring holiday misses carnaval (2025, 2027, 2030), a "Carnavalvakantie (zuid)" for the week many schools there take instead, into the calendar `feestdagen` of `lvdar@lvdar.nl`, daily, because Stalwart cannot subscribe to ICS feeds. It writes over CalDAV on the loopback management listener as the recovery admin impersonating the account (`lvdar@lvdar.nl%admin`). Events are stored under a hash of their content, so each run only deletes and uploads what changed; anything added to that calendar by hand is deleted on the next run, and so are past years once they drop out of the feeds (about five years back). Thunderbird subscribes to it read-only. Run it by hand with `systemctl start holiday-calendar`.

`services.birthday-calendar` turns the birthdays (`BDAY`) of the contacts in every address book of `lvdar@lvdar.nl` into yearly all-day events, "Verjaardag <name> (<birth year>)", in that account's calendar `verjaardagen`, hourly, the same way: CardDAV and CalDAV on the loopback listener as `lvdar@lvdar.nl%admin`, events stored under a content hash, hand edits undone on the next run. Yearless birthdays (vCard 4 `--MMDD`, or a year before 1900 or Apple's `X-APPLE-OMIT-YEAR`, the placeholders of clients that cannot store one) get no year; 29 February falls on 28 February in common years. Events carry the category `Birthday`, which Thunderbird colours; Thunderbird subscribes read-only. Run it by hand with `systemctl start birthday-calendar`.

## pioneer

Raspberry Pi 3 publishing endeavour's iDRAC. Its host entity `excludes` `core.yubikey` and the home baseline's editor and CLI tools (nvim, git, tmux, yazi, oh-my-posh, …), keeping only `home.core`, zsh, ssh and theme-options: the 16G SD card has no room for them and every one is an emulated aarch64 build. For the same card it ships only the Broadcom wireless firmware (not linux-firmware), no `nixos-rebuild` (`system.disableInstallerTools`), and no pinned nixpkgs source in its registry; its system closure is about 1.3G.

The iDRAC (iDRAC8, firmware 2.21, no Redfish) is reached on the LAN at `192.168.2.111`, over the mesh at `https://idrac.lvdar.nl`, and by SSH as `ssh idrac` (a jump through pioneer with the RSA `id_idrac` key; see `hosts/voyager.nix`).

- **Set iDRAC passwords in-band, letters and digits only.** Passwords with special characters, and passwords set through the web UI, can pass IPMI yet fail the web login with `RAC0212` (2026-10-30, both accounts). From endeavour, which needs no old password: `nix run nixpkgs#ipmitool -- user set password <id> "$pw" 20`, then `user test <id> 20 "$pw"` (ids: `root` 2, `lvdar` 3; `ipmitool user list 1`).
- `ipmitool mc reset cold` on endeavour restarts only the BMC (clears login blocks and stale web sessions); restart `ipmi-fan-control` on endeavour afterwards, since it fails while the BMC is away.
